Technical environment

Professional tools, owned by the school.

One selection criterion: every service (hosting, database, images) is tied to an account owned by ENC Bessières, which can access or migrate its data at any time.

  • Next.js / React — front-end framework: fast pages, reusable components
  • Vercel — hosting and automatic deployment on every change
  • Cloudinary — image storage and optimisation (profiles, posts, blog)
  • OAuth 2.0 (Google) — one-click sign-in, no password stored
  • Git / GitHub — full history of code changes
  • VS Code, ESLint, Prettier, DevTools — editing, code quality, interface testing

Challenges and solutions

Learning to research, isolate, solve.

Setting up OAuth 2.0 authentication

Reading the official Next-Auth documentation, testing the flow step by step, configuring redirect URLs in the Google Cloud console.

Uploading images with Cloudinary

After several attempts, direct upload from the browser (unsigned upload) to avoid routing the image through the Next.js server.

Environment variables in production

Keys worked locally but not on Vercel: I learned to declare them in the Vercel dashboard.

Managing role-based permissions

Protecting API routes on the server AND hiding buttons on the client: the role is checked at every level.

Updating the feed in real time

New posts only appeared after a reload: I used SWR to refresh data automatically.

Responsive design (mobile and desktop)

Some pages displayed badly on phones: screen-by-screen testing with Chrome DevTools and CSS adjustments.

Key takeaways. I discovered Next.js, Cloudinary, OAuth 2.0 and Vercel, and learned to work independently in an organised way and to handle the unexpected. Reading documentation, isolating a bug and finding a solution matter as much as coding.
